# Q6. SQLインジェクション

## 問題

SQLインジェクションとは何か説明してください。

また、MyBatisで防ぐための実装上の注意点を述べてください。

## 回答

SQLインジェクションとは、第三者がSQLに不正な入力を追加し、データベースから情報を取得したり、改ざんしたり、削除したりしてしまう攻撃のことを言います。対策をしていない場合、入力されたものが、ただの文字列ではなく、すべてに当てはまるという命令などに変わってしまいます。

それを防ぐためには、SQLの中身の値を仮に `?` で置き、データベースに先に命令を伝え、後から利用者の入力する値を入れることにより、その値をただの文字列として扱います。

MyBatisでXMLを書く際には、`${}` で作るのではなくて、`#{}` で値を入れることによって、プレースホルダーの対策を取ることができます。`#{}` では、命令だけが先に伝わり、値は後から伝わります。一方、`${}` では、入力が直接の命令になってしまうため、第三者からの入力で悪用されてしまう恐れがあります。

## 理解のメモ

- たとえ：申込書。A は、利用者が書いた文字ごと命令文として読む。B は、命令文を先に決めて、空欄に書かれたものは「そういう値」としてだけ読む。`${}` が A、`#{}` が B。
- 例：メールアドレス欄に `' OR '1'='1` と入力される。
  - `WHERE email = '${email}'` は `WHERE email = '' OR '1'='1'` になる。入力の中の `'` が文字列を閉じてしまい、続きが命令になる。`'1'='1'` は常に正しいので、全員分が当てはまる。
  - `WHERE email = #{email}` は `WHERE email = ?` になり、値は別に送られる。`' OR '1'='1` という名前のメールアドレスを探すだけなので、誰も見つからない。
- 分かれ目は、値が「確定しているか」ではなく、入力された文字が SQL の文の中に入り込むか、別に送られるか。
- `${}` でも普通の入力なら正しく動くので、普通の入力だけで試していると危険に気づけない。
- 弱点があるのは SQL という言語ではなく、入力をつないで SQL を組み立てるアプリの作り方。
- `?` に入れられるのは値だけ。並び替えの列名などは `?` にできないので、あらかじめ決めた候補の中からだけ選ばせる。
- このアプリの実装：マッパーの XML はすべて `#{}` を使い、`${}` は使わない決まり（NFR-SEC-05）。例は `UserMapper.xml` の `findByEmail`（`WHERE email = #{email}`）。
- ユーザー検索では `%` や `_` をエスケープしているが、これは LIKE の「何にでも当てはまる記号」として働かないようにするため。SQLインジェクションを防いでいるのは `#{}` のほう。
