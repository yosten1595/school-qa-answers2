# Q13. 環境ごとの設定管理

## 問題

プロファイルの仕組みと、環境ごとに設定を分ける理由を説明してください。

## 回答

開発環境、テスト環境、本番環境というように、DBの接続先や秘密鍵などの設定をまとめた複数のプロファイルを用意しておきます。起動するときにどのプロファイルを使うかを指定すると、Spring Bootがそのファイル名を読み、共通の設定をそのプロファイルの設定で上書きします。この仕組みにより、コードを変えずに、環境ごとの設定に切り替えることができます。

この利点としては、開発やテスト、そして本番の際にコードの中身を変える必要がないため、ヒューマンエラーが起きにくいことがあります。また、認証機能があるようなアプリにおいては、本番では秘密情報が漏れてはならないため、秘密鍵を別で用意しておかなければいけません。開発用の秘密鍵はチームが知っていてもいいですが、本番の秘密鍵が知られると悪用される危険性があるためです。本番の秘密鍵はGitHubで公開されないように、.gitignoreに入れた別のファイルや環境変数を用いて対応します。

## 理解のメモ

- プロファイル ＝ 設定のセットに名前を付けたもの。`application.properties`（共通）、`application-dev.properties`（dev）、`application-prod.properties`（prod）のように分け、起動するときに `spring.profiles.active=prod`（環境変数なら `SPRING_PROFILES_ACTIVE=prod`）で選ぶ。
- 上書き ＝ 同じ項目があれば、プロファイルの値に置き換える。プロファイルに書いていない項目は、共通の値のまま。たとえ：いつもの時間割（共通）と、今日の変更のお知らせ（プロファイル）。だから、プロファイルには環境ごとに違う項目だけを書けばよい。
- プロファイルのファイルは、DB の中ではなく、バックエンドのプログラムの中（`backend/src/main/resources/`）にある。書いてあるのは DB の住所。流れ：起動する → 設定ファイルを読む → その住所の DB に接続する → 以後の SQL はその DB に送られる。
- 環境ごとに変わるのは DB だけではない。このアプリの例：DB の接続先、JWT の秘密鍵、Cookie の Secure 属性（開発は http なので false、本番は true）、画像の保存先（開発はエミュレーター、本番は S3）。
- 本番でも開発用の秘密鍵を使うと、攻撃者が本物と見分けのつかないアクセストークンを自分で作れて、誰にでもなりすませる（Q1）。
- プロファイルは「どの設定を使うかを切り替える」仕組みで、「秘密を隠す」仕組みではない。`application-prod.properties` も GitHub に置かれるので、秘密鍵を書くと読まれてしまう。
- 環境変数 ＝ パソコンやサーバー（OS）が持っている、名前付きのメモ。ファイルと違ってコードと一緒に GitHub に置かれず、そのサーバーの中だけにある。サーバーごとに別の値を覚えさせられる。本番の値は、サーバーの設定や AWS Secrets Manager などの秘密を保管するサービスに入れる。
- このアプリは、プロファイル別のファイルを使わず、`app.auth.jwt-secret=${JWT_SECRET:dev-only-secret-...}` のように、環境変数があればその値、なければ `:` の後ろの開発用の値を使う形で切り替えている。GitHub にあるのは「環境変数を読む」という指示だけ。
- サーバーとデータベースは別のもの。サーバーは頼まれたことをして返すコンピューター（建物）、データベースはデータをしまう仕組み（倉庫）。DB が動いているコンピューターを DB サーバーと呼ぶ。開発では自分の PC 1台に両方があり、本番では EC2（バックエンド）と RDS（DB）の別々のコンピューターになる。
- EC2 はコンピューターそのものを借りるサービス、RDS はデータベース付きのコンピューターを借りるサービス（バックアップや更新は AWS がする）。RDS の住所（エンドポイント）を本番の環境変数に入れ、セキュリティグループで EC2 からだけ接続できるようにする。
- 分ける理由：アプリを作り直しても DB のデータは消えない、EC2 だけ台数を増やせる、DB をインターネットから直接触れない場所に置ける。
- EC2 に自分で PostgreSQL を入れて DB サーバーにすることもできる（安いが、バックアップや更新は自分でする）。たとえ：空き部屋を借りて自分で倉庫を作るか、管理人付きの倉庫（RDS）を借りるか。
- テストは、`src/test/resources/config/application.properties` で設定を上書きしている。
