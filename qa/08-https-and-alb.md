# Q8. HTTPSと本番セキュリティ

## 問題

以下について説明してください：

- ALBを使った場合のSSL/TLS証明書の配置場所
- ALB〜バックエンド間通信のHTTPS必要性

## 回答

HTTPの通信をSSL/TLSによって暗号化したものをHTTPSと言います。証明書は、管理者がサーバーに対してセキュリティを求めた時に、認証局から発行されます。ブラウザが接続する時には、ブラウザとサーバーで共通の鍵を持ち、通信が暗号化されます。よって、ブラウザからの通信はHTTPSを通り、安全にサーバーへ行くことができます。

ALBを使った場合、証明書はACMに保存し、ALBのHTTPSリスナーと紐付けます。ブラウザが最初に通信する相手はALBであり、ALBがそこからバックエンドへ振り分けるためです。ブラウザからALBまでの間はインターネットを通るため、暗号化されないといけないので、HTTPS形式を取ります。

ALBからバックエンドへの通信は、インターネットではなくAWSのVPC内を通るため、必ずしも暗号化しなくてもよく、このアプリではHTTP形式でルールを設定しています。ただし、VPCの中に入り込まれた場合には通信を盗まれる危険性があるため、盗まれたくない情報があるのであれば、ALBからバックエンドへの通信も、HTTPSで暗号化する必要があります。

## 理解のメモ

- たとえ：手紙（通信）を鍵のかかった箱（HTTPS）に入れ、町の中（インターネット）を通して会社に送る。受付（ALB）が箱を開け、会社の廊下（VPC）を通って担当者（バックエンド）に届ける。ALB で暗号化が終わることを「HTTPS の終端」という。
- 暗号化するのは SSL/TLS という仕組み。証明書は、相手が本物（例：`sns.example.com`）だと証明するもの。暗号化がどれだけ強くても、相手を間違えていれば意味がない。
- 証明書は「アクセスしようとしたドメインに間違いなくつながっている」ことの証明。詐欺サイトでも自分のドメインの証明書は取れるので、「良いサイトだ」ということまでは証明しない。
- リスナー ＝ ALB の中にある窓口。どのポートで待ち受け、来た通信をどうするかを決める設定。HTTPS リスナー（443番）は証明書を見せて暗号を解き、バックエンドへ渡す。HTTP リスナー（80番）は「443番へ」と案内する（リダイレクト）。ブラウザは窓口に来る側。
- 場面は2つある。準備（公開前）：開発者が認証局に証明書を頼み、ACM に保存し、HTTPS リスナーと紐付ける。本番（接続のとき）：利用者のブラウザが HTTPS リスナーに来て、証明書を確かめる。ブラウザは相手を探すのではなく、行き先は URL で決まっている。
- 接続の流れ：HTTPS リスナーが証明書を見せる → ブラウザが本物か確かめる → ブラウザと HTTPS リスナーが一緒に共通の鍵を作る → その鍵で暗号化して送る → HTTPS リスナーが暗号を解いてバックエンドへ渡す。共通の鍵は、証明書の発行時ではなく、接続するときに作る。
- 鍵そのものは渡さない。お互いに材料を交換して、それぞれの手元で同じ鍵を作る。
- HTTPS が守るのは通信の途中（盗み見や書き換え）。箱の中身に悪いものが入っている SQL インジェクション（Q6）や XSS（Q7）は防げない。
- 証明書は、ブラウザがサーバー側を確かめるもの。利用者が誰か、操作してよいかを確かめるのは認証・認可で、バックエンドの仕事（Q4）。リスナーは、ログインしていない人の通信も受け取って渡す。
- 認証局（CA）は、証明書を発行する実在の組織（DigiCert、Let's Encrypt、Amazon Trust Services など）。ドメインを管理している人かどうかを、DNS に決められた値を書かせるなどして確かめてから発行する。ブラウザや OS は、信頼する認証局のリストを最初から持っている。
- ACM は、証明書の発行を頼み、保管・更新する AWS のサービス。証明書を見せるのは ALB。
- 証明書を ALB に置けば、バックエンドが10台あっても管理する証明書は1つで済む。
- ALB〜バックエンドを HTTP にするのは「何も守らない」ではない。セキュリティグループで、バックエンドは ALB からの通信だけを受け付ける。アドレスを知られただけでは入れない。
- それでも HTTPS にするのは、VPC の中のサーバーが乗っ取られる、設定を間違える、内部の人が悪用する、といった場合への備え。銀行や医療のように情報が重いアプリや、法律・業界の決まりで求められる場合は HTTPS にする。
- このアプリの設計（検討段階の案）：ALB で HTTPS を終端し、HTTP:80 は HTTPS にリダイレクトする（NFR-SEC-12）。ALB から EC2 の nginx へは HTTP:80 で、EC2 は ALB からの 80 番だけを受け付ける（`docs/06_infrastructure.md`）。
