# Q12. MyBatis vs JPA

## 問題

以下の観点で違いを説明してください：

- SQL制御
- 学習コスト

## 回答

MyBatisとJPAを比較して、以下の2つの点について説明します。

1点目のSQL制御に関しては、MyBatisは、Javaから渡された値を開発者が書いたSQLに当てはめる役割をします。そのため、SQLは開発者が書く必要がありますが、開発者が思った通りに書くことができるため、制御しやすいです。反対に、JPAは、開発者が短いコードを書くだけで、JPAが自動でSQLを書いてデータベースへ伝えてくれるため、楽ではありますが、開発者の思い通りにいかない場合があります。

2点目の学習コストについては、MyBatisの場合は、開発者がSQLを学ぶ必要があります。JPAの場合は、JPAの仕組みを理解する必要があります。理解していないと、一見、開発者が書くコードは短く楽そうに見えますが、JPAが自動で書くSQLが多くなってしまい、処理が遅くなる危険性があります。

## 理解のメモ

- SQL を書くのは、MyBatis では開発者、JPA では JPA。MyBatis は、書かれた SQL を実行して結果を Java のオブジェクトに詰め、`#{}` に値をはめ込む。
- JPA も裏では必ず SQL を作って送っている（DB が分かるのは SQL だけ）。開発者から見えにくいだけ。
- 例：「メールアドレスでユーザーを探す」は、MyBatis なら Java のメソッドと XML の SQL を書く。JPA なら `findByEmail` というメソッド名だけで、JPA が SQL を作る。
- JPA は「始めるのは楽、使いこなすのは難しい」。投稿20件と投稿者を表示するだけで、投稿1回＋投稿者20回の計21回の SQL が送られることがある（N+1 問題）。直すには、JPA がいつどんな SQL を作るかを学ぶ必要がある。
- MyBatis で学ぶのは、SQL（読めるだけでなく書ける）と MyBatis の書き方。SQL は MyBatis 以外でも使える一般的な知識。
- どちらがメモリを多く使うかは、使い方によって変わり、一概には言えない。
- 使い分けの目安：単純な登録・更新が多いなら JPA が楽。集計や検索など、SQL を細かく書きたい処理が多いなら MyBatis。
- このアプリの選択：MyBatis（XML マッパー）。タイムラインの件数集計や検索の並び順など、SQL を直接書きたい処理が多いため（`docs/08_tech_stack.md`）。
- JPA は Java の決まり（仕様）の名前で、実際に動かす部品は Hibernate など。Spring Boot では Spring Data JPA を通して使うことが多い。
